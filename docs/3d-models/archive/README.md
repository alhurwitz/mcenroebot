# McEnroe V2 — Arm Design ("Aim-and-Swat" Turret)

## The pivot

The original `PROJECT_PLAN.md` called for a dual-wheel ball launcher. This is the
arm-based alternative AJ asked for in V2: a real paddle on a swinging arm, aimed
by a 2-DOF turret. It's harder than a launcher but it's the McEnroe-y answer —
the robot actually *hits* the ball with a paddle instead of spitting it out of a
nozzle.

## Architecture

Three independent axes:

1. **Yaw** (J1) — base rotation. Aims the strike plane left/right.
2. **Pitch** (J2) — shoulder tilt. Aims up/down and sets approach angle.
3. **Swing** (J3) — fast paddle stroke. Open-loop, fired at a predicted T0.

J1 and J2 are MG996R metal-gear servos (slow-but-accurate aiming).
J3 is a brushless motor (A2212 1000KV from the existing BOM) — used for raw
swing speed, not closed-loop position control.

The control loop:
1. Camera tracks ball → trajectory predictor estimates contact point + time.
2. J1 + J2 move to point the strike plane at the predicted contact (settles
   well before T0).
3. At T0 − swing_latency, fire J3 throttle. Paddle sweeps through the plane.
4. Ball gets hit (in theory). Trash talk plays regardless of outcome.

## Why not a full 6-DOF arm

A real arm with closed-loop joint control needs harmonic drives or high-Kv
servos that cost more than the rest of the BOM combined. We don't have the
torque budget on hobby servos to drive a 0.25m arm fast enough. The compromise:
slow aiming + dumb fast swing.

## Honest limitation: paddle tip speed

A2212 1000KV at full throttle on 3S is ~11,000 RPM — way too fast for direct
drive on a paddle. At 10–20% throttle for ~150ms we get a 90° sweep with paddle
tip speed around 2–3 m/s. Recreational ping pong returns want 4–8 m/s tip
speed. So this first pass will probably hit the ball but won't drive it back
hard. That's fine — first iteration. Next iteration options:

- Gear down a higher-torque BLDC (or use a sensored brushless gimbal motor).
- Use a beefier outrunner (e.g. 2814 700KV) on a 4S pack.
- Add a torsion spring that pre-loads the arm and gets released by a servo.

## Parts (in this folder)

| File | What it is | Material | ~Print time |
|---|---|---|---|
| `01_base_plate.stl` | Bolts to a weighted base, mounts the yaw servo | PETG+ | ~2h |
| `02_yaw_bracket.stl` | Rides on yaw servo horn, mounts pitch servo | PETG+ | ~2h |
| `03_pitch_bracket.stl` | Rides on pitch servo horn, holds the BLDC + bearings | PETG+ | ~3h |
| `04_swing_arm.stl` | Bolts to BLDC shaft, holds the paddle clamp | PETG+ | ~1.5h |
| `05_paddle_clamp.stl` | Two halves that clamp a paddle blade | PLA matte | ~1h |

Use **PETG+** for everything load-bearing (PLA creeps under sustained torque).
Paddle clamp is fine in PLA since it's only loaded in compression.

## How parts mate

```
       [ paddle blade ]
              │
       [ paddle clamp ]   ← M3 × 4, pinches paddle blade
              │
       [ swing arm ]      ← M3 set-screw on BLDC shaft
              │
        ( A2212 BLDC )
              │
       [ pitch bracket ]  ← 608 bearings flank the motor
              │
        ( MG996R J2 )
              │
       [ yaw bracket ]
              │
        ( MG996R J1 )
              │
       [ base plate ]
              │
        weighted base (table-clamp, sandbag, anything heavy)
```

## Regenerating parts

All STLs are generated by `generate_parts.py` in this folder. Tweak constants
at the top, re-run, get new STLs:

```bash
cd 3d-models
python3 generate_parts.py
```

## Print settings (Bambu Studio, P2S)

- Nozzle: 0.4mm
- Layer height: 0.20mm (0.16 if you're feeling patient)
- Walls: 4 perimeters
- Infill: 40% gyroid for structural parts, 15% for paddle clamp
- Supports: tree, only on overhangs >55°. Most parts designed to print
  flat-side-down with no supports needed.
- Brim: 5mm on the swing arm (long thin part, wants to lift)
